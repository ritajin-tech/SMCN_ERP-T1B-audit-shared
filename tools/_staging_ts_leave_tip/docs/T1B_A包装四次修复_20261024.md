## 四点残项 → 修复落点

### 残项 1：principalSnapshot 契约 —— 冻结快照丢了 `status`，真实核心会整体失效（真 bug）
- **核实**：既有核心 `ts_leave_tip_core.js` 第 191–193 行要求解析器返回 `{status:'OK', employeeId}`，否则 `pr.status` 为 `undefined !== 'OK'` → 永远走"身份未通过校验"分支。v4 固化的是 `Object.freeze({employeeId})`（缺 `status`），**功能会整个失效**。
- **修复**：冻结快照改为 `Object.freeze({ status: 'OK', employeeId })`（`resolvePrincipal` 已在此前校验 `pr.status==='OK'`，冻结固定值诚实且必要）。
- **验证（真实核心契约兼容性测试，提交方本地实跑）**：注入真实核心 + 设 `TRUSTED_RESOLVER` 返回 `{status:'OK',employeeId:'E1001'}` → `getLeaveTipSafe` 实际产出 `OK` 与本人事件；另加**回归守卫**——若冻结快照仅 `{employeeId}`（修复前形态），真实核心返回非 OK（证明该 bug 确会失效，故修复必须冻结 `status:'OK'`）。

### 残项 2：wrapResponse 未知/隐私态未 fail-closed —— 敏感 tip/events 可能外泄
- **核实**：v4 对未知 `status` 仅改码为 `FETCH_FAILED`，仍保留原 `tip/events`；`PRIVACY_BLOCKED` 亦未走清空路径。失败/隐私态若携带业务数据，单改 status 并不失败封闭。
- **修复**：`wrapResponse` 改为 fail-closed——仅 `OK` 透传 `tip/events`；`AUTH_REQUIRED/UNAUTHORIZED/PRIVACY_BLOCKED` 直接返回固定隐私封闭；其余一切状态一律 `tip:null, events:[]`（含 `MIRROR_STALE` 等失败态）。
- **验证**：哨兵测试——核心返回 `{status:'SENTINEL', tip:'SECRET_TIP_SENTINEL', events:[{who:'E9999'...}]}`（未知态/失败态/隐私态各一）→ 包装后 `tip` 为 `null`、`events` 为空、序列化结果不含 `SECRET_TIP_SENTINEL` 与 `E9999`；`OK` 态仍正确透传本人业务内容。

### 残项 3：stage4 畸形 CSV 集成测试假绿 —— 实际在 SHA 比对步就 exit 1，没证明解析器拦截
- **核实**：原测试改了 `before` 文件却未更新 `manifest.beforeSha256`，故在证据 SHA 比对步即 exit 1，未触达解析器；且 `t3='a"x,b'` 测的是字段中引号，未覆盖"闭合引号后非法字符"分支。
- **修复**：集成测试改用**相同畸形字节**写入 `before` 与 `after` 并**双 SHA 均更新**，使证据 SHA 比对通过、失败必须来自解析器（排除字节漂移/SHA 先行拒绝）；`t3` 改为 `'"a"x,b'`（覆盖闭合后非法字符分支）。
- **验证**：`stage4 畸形 CSV→解析器拦截 exit 1 FAIL（非 SHA 先行拒绝）` 通过；`parseCsv 闭合引号后非法字符→抛错` 覆盖所声称分支。

### 残项 4：capturedAt 仅正则形状 / CSV 边界规则未明
- **核实**：`capturedAt` 正则允许 `2026-99-99T99:99:99+99:99` 这类"形状合法但日历/时标/偏移非法"的值；空引号字段 `""` 在文件末尾被丢成无记录、裸 CR 静默跳过无明确规则。
- **修复**：`capturedAt` 升级为**真实 ISO 校验**——显式年/月/日（禁 2/30、4/31、非闰年 2/29）+ 时/分/秒范围 + 偏移范围 `[-12:00,+14:00]`（拒绝 `+15:00` 等）；允许纯日期或完整时间戳，由工具用途区分。`parseCsv` 明确终止符规则：CRLF 作单一终止符、裸 CR 亦终止（不静默跳过致行合并）；空引号字段 `""` 显式保留为单格空行（不静默丢弃）；畸形仍 fail-close。
- **验证**：`capturedAt` 边界测试——`2026-02-30`/`2026-13-01`/`2026-10-24T25:00:00+08:00`/`2026-10-24T08:15:00+15:00` 均判不合法，`2026-10-24`(纯日期)合法；CSV 边界测试——`""`→单格空行、CRLF→两行、裸CR→两行(不合并)。
