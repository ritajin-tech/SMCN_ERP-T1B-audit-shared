## 落点 1 · stage4 失败路径结构化错误码 + 断言锚定

**文件**：`stage4_hash_check.js`（main 各失败出口）、`stage4_tests.js`（`runStage4` 捕获 stderr + 畸形断言）

- `stage4_hash_check.js` 所有失败出口补结构化错误码前缀：
  - `[ERR_MANIFEST_PARSE]` / `[ERR_MANIFEST_INVALID]` — manifest 解析/校验
  - `[ERR_SHA_BEFORE]` / `[ERR_SHA_AFTER]` — 证据 SHA 不符
  - `[ERR_CSV_PARSE]` — CSV 解析异常（畸形）
  - `[ERR_COL_RANGE]` — 非目标列索引越界
  - `[ERR_CSV_WIDTH]` — 非目标区域提取（宽度不一致/畸形）
  - `[ERR_EMPTY_PROJECTION]` — 两端空投影
  - `[ERR_HASH_DRIFT]` / `[ERR_WRITE_SET]` — 最终 FAIL 的漂移/写集分支（原"STAGE4 FAIL ❌"合并输出拆为带码 reason）
- `stage4_tests.js` 的 `runStage4` 改为捕获子进程 stderr 存入 `lastStderr`；畸形 CSV 集成测试断言升级为：
  ```
  malCode === 1 && /\[ERR_CSV_PARSE\]|CSV_MALFORMED/.test(lastStderr)
  ```
  即：失败必须来自解析器（证据 SHA 双更新已通过比对），且 stderr 含 `[ERR_CSV_PARSE]` 结构化码——杜绝其他失败路径假绿。

## 落点 2 · wrapper 第12节三态区分

**文件**：`wrapper_negative_tests.js`（第12节）

`require('../ts_leave_tip_core.js')` 的失败按 `e.code === 'MODULE_NOT_FOUND'` 区分三态：
- `executed`：核心同仓加载成功 → 跑真实核心契约兼容 + 缺 status 回归守卫（本地 35/35）。
- `skipped_missing`：核心文件确不存在（MODULE_NOT_FOUND，且路径含 `ts_leave_tip_core`）→ 预期跳过，显式打印 `SKIPPED_MISSING` 并记一条 `check(..., true)` 标记（clone 34/34）。
- `load_failed`：核心存在但 `require` 抛错（语法/依赖等，非 MODULE_NOT_FOUND）→ **显式失败**（`check(..., false)` → 整套件 exit 1），不静默归为跳过。

三态显式覆盖 Tom 建议：缺失与加载失败不再同一 PASS。
