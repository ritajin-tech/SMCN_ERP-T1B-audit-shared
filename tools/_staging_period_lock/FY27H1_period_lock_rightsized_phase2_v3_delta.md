## 修订 1（对应问题 1：重核后竞争窗口 / check-then-act）

**v2 原措辞的问题**（已核实属实）：M8"写入前重核行版本"只消除"重核前被改"的情形；重核通过之后、业务写实际完成之前，仍存在"本请求重核通过→另一写者改期间/版本→本请求按旧快照写入"的窗口（R10 只覆盖前者）。且"再次读"不能证明竞争消失。

**v3 修订（承诺缩小到可证明边界，不造机器）**：

- **M8 改为「guard 临界区串行化」**：对**已接入 guard 的参与入口**，版本重核与业务写置于**同一受控串行临界区**内完成——同一 guard 执行边界内，参与入口请求不可被另一参与入口请求交叉（以 GAS 单实例执行顺序 + guard 内串行为边界；编码时以单一函数栈内"重核→写"不交出控制权实现）；重核不符即拒。
- **明确缩小保证**：上述串行边界只覆盖**参与入口之间的竞争**。**外部不参与者**（直接改表的其他 GAS/脚本/人工路径）**不在覆盖范围，明确列为未覆盖**，仅由 X2 周期检测告警兜底。
- **删去任何"任何竞争均能发现后拒绝"式表述**：竞争保证的精确边界＝「参与入口间串行 + 重核不符即拒；外部写者未覆盖，仅告警」。
- R10 拆分为：
  - **R10a**（保留）：他人改于重核之前 → 拒；
  - **R10b**（新增）：重核通过后、写完成前，另一**参与入口**请求改同行 → 串行边界阻止交叉，后写者重核失败 → 拒；
  - **R10c**（新增，未覆盖登记）：**外部写者**于任意时刻改同行 → **不宣称被发现或拒绝**；仅 X2 检测告警 + 人工处置。
- 不引入自动恢复、条件写（Sheets API 无条件写原语，不宣称具备）、分布式锁。

## 修订 2（对应问题 2：批量中断语义过度承诺）

**v2 原措辞的问题**（已核实属实）：R12"一批中段失败→整批拒、不留半成品"在无事务/恢复机制下不成立——既有写路径若前段已写、后段失败，返回拒绝不能撤销已发生的写入。

**v3 修订（承诺拆分，明确缩小保证）**：

- **R12a「批前校验·不合格零写」（可承诺）**：批量写入前对全批行执行 guard 校验，**任一不合格则零写**（校验先于一切业务写，此承诺有机制支撑）。
- **R12b「业务写中途失败·结果不确定」（明确缩小为保证外）**：业务写执行中途失败（API 中断/超时/异常）→ **结果不确定，列为已知限制**；已写入的部分行**不回滚、不补偿、不自动恢复**；由 X2 检测 + 告警 + 人工处置。**删去"整批拒、不留半成品"表述**——该表述只在批前校验阶段成立，业务写中途不成立。
- 不为解决 R12b 引入事务机制或自动回滚（遵 23:59"不要为此自动回滚或扩大生产动作"）。
