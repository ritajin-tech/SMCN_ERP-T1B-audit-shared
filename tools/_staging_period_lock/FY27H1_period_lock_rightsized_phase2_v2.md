## 1. 右 Sized 定位（一句话）

**主路径 = 拒绝，不是改写。** 提交函数对「向已关账期间写入」直接拒绝并提示，不改写任何数据、不引入 opId 全链路 / staging / 不确定性建模 / 自动恢复机器；外部写者用只检测告警兜底。**例外路径（双签更正）整体暂缓**，待审计 tab 授权就绪后独立送审，不夹带于本主路径交付物。

## 2. 主路径设计（拒绝式 guard）

| # | 组件 | 设计 | 对应既有约束 |
|---|---|---|---|
| M1 | 写网关双向日期 guard | **入口分列**：① 已接入 guard 的可控入口——ts-manager 提交函数路径（submitBatch / updateTimesheet / softDeleteRecord / tsAppendRows / tsPatchCells，以已只读取得的 HEAD 快照为准，编码前复核）：新增看新 `fillDate`；修改/删除**同时检查原记录期间 + 新记录期间**；② 外部写者（直接改表的其他 GAS / 脚本 / 人工路径）：不在 guard 覆盖范围，仅 §4 事后检测。未取得代码/部署入口证据前，**不宣称全覆盖** | §8 边界2 |
| M2 | 锁阈值 | `fillDate < 2026-10-01` 关账（含 pre-H1 历史一并冻结）；`2026-10-01` 起全开 | §8.1 ①（Rita 15:39 确认） |
| M3 | 锁政策态持久化 | 锁状态持久化存储，独立于 `FEATURE_ENABLED`；**版本回退须保留执行锁的受控入口或先拒绝写入（fail-closed）**——持久状态本身不是执行约束，不得以"状态还在"代替实际拒绝能力 | §8 边界3 + Tom 23:29 ③ |
| M4 | `futureOpen` policy | 独立业务标志（默认开），变更须 Rita 显式记录；不随本改动自动开启、不依赖 `FEATURE_ENABLED=false` | §8.1 ③ / §8 边界3 |

| E2 | 一次授权一戳 | 每次解锁授权单次、限定范围（主体/行/期间/操作）；完成即耗尽，不恢复任何写权限 |

## 6. 明确不做清单（右 Sized 的边界）

- 不做 opId 全链路幂等机
- 不做 staging 持久化与合成状态组合总表
- 不做不确定性建模 / 写前门禁放行分支
- 不做自动回滚 / 自动恢复
- **不宣称 guard"全覆盖"**（外部写者仅事后检测，M1/§4）
- 不为 HTTP 400 主动重授权 / 扩权限 / 调用生产（§8 边界5 维持）
