## 1. 右 Sized 定位（一句话）

**主路径 = 拒绝，不是改写。** 提交函数对「向已关账期间写入」直接拒绝并提示，不改写任何数据、不引入 opId / staging / 不确定性建模 / 自动恢复机器；例外路径（双签 7 天更正）与外部写者用**保守隔离 + 只检测告警**兜底。

理由：原子恢复协议针对的是开放域问题（并发 / 崩溃 / 外部写者 / 幂等的完备恢复，无有限收敛点）；而业务目标有界——「10-01 前的旧行不被改」。为罕见例外路径（双签更正，一季可能仅数行）造主路径（锁数千行）的完整恢复机器是尾巴摇狗。

## 3. 例外路径设计（保守隔离）

双签 7 天历史更正的处置原则：**解锁即隔离，不做自动恢复**。

| # | 组件 | 设计 |
|---|---|---|
| E1 | 授权 | Rita + sysadmin 双签；单次解锁最长至更正完成、封顶 7 天自动过期；仅限误填历史行更正（§8.1 ②） |
| E2 | 一次授权一戳 | 每次解锁授权为单次、限定范围（主体 / 行 / 期间 / 操作）；**授权完成即耗尽，不恢复任何写权限**——采纳 Tom 22:12 第①点（重锚只更新已验证基线，不恢复写权限） |
| E3 | 审计 | 解锁即入 `工时表解锁审计` tab（谁 / 哪行 / 何时 / 原因）；该 tab 本身是新生产写，**须 Phase 3 另行授权**（§8 边界4） |
| E4 | 每日对账 | 例外路径解锁记录每日报所有者；无自动恢复动作 |
| E5 | 授权凭证 | 例外路径的授权以稳定 reqId 映射固定意图摘要 + 作用域绑定签发——采纳 Tom 22:12 第③点（内容指纹不能单独定义请求身份） |

## 6. 明确不做清单（右 Sized 的边界）

- 不做 opId 全链路幂等机（仅例外路径用稳定 reqId 绑定授权，E5）
- 不做 staging 持久化与合成状态组合总表
- 不做不确定性建模 / 写前门禁放行分支
- 不做自动回滚 / 自动恢复（X2、E4）
- 不为 HTTP 400 主动重授权 / 扩权限 / 调用生产（§8 边界5 维持）
