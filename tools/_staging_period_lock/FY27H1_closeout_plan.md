## 1. 目标与背景

- 把 `fillDate < 2026-10-01` 的工时记录**机械关账**，清理后只允许继续填报十月起的日期。
- 等价于「收尾 FY27H1」：FY27H1 = 2026-04-01 ~ 2026-09-30（含更早历史一并冻结）。
- 价值：消除「有人回头改九月 / 补录旧日期」把 H1 报表、考评（FY27H1 口径已定）、对账全部搞乱的风险——对脆弱实时工时系统是标准 *period close* 控制。

## 2. 范围与锁定口径

- **锁定键**：`fillDate`（工时发生日），非提交日、非行写入时间。
- **阈值**：`fillDate < 2026-10-01` → 关账；`2026-10-01` 起（含十月、十一月、未来）全开。
- **作用对象**：生产工时表 `DB_工时流水` 经 ts-manager 填报页写入的行。
- **不波及**：请假提示读历史镜像（只读，不受影响）；已在途的请假提示部署。

## 3. 设计决策（已与 Rita 定稿）

| # | 决策 | 选择 | 理由 |
|---|---|---|---|
| D1 | 锁类型 | **软锁** | 默认只读+灰标；Rita/sysadmin 可**一键解锁**做更正并留审计。硬锁会逼出线下影子表，反而更乱。 |
| D2 | 拦截位置 | **提交函数拦截**（主）+ sheet 保护（次，防御） | GAS 写入能绕过 sheet 保护，故必须在提交函数里拦；sheet 保护仅作二次警示。 |
| D3 | 关账顺序 | **verify-then-lock** | 先扫 H1 行做完整性/总额核验，只标缺陷供审、**不动数据**；确认后再锁。 |
| D4 | 与请假提示关系 | **解耦** | 独立改动，单独走 staged + 一键关闭开关 + fail-closed，不跟 v5 混推脆弱实时系统。 |
| D5 | 「清理」口径 | **对账核验后锁**（Rita 选定） | 扫 H1 行标疑似缺陷→Rita 审→（可选）修正→锁。不盲目动历史数据。 |

## 4. 操作流（Phase 0 → 3）

> **规范优先级**：§8 设计约束（边界 1-7）为权威规范。本节 Phase 0-3 与 §5 的操作描述若与 §8 冲突，以 §8 为准，且正文须对齐 §8（操作员不得在两处任选）。

  - 对齐 §8 边界1：扫描分 H1 / pre-H1 两段独立报告；日期解析失败不得变放行；缺月/合理性须来源规则支持，仅疑似清单、不作考评/薪酬裁定。
