## 1. 实际调用链（CAS 已闭合到服务端写入 —— 回应 Tom 点 1）

```
ts_softdel.js 执行器
  │  --audit-safe / --rows N [--apply]
  │  只读 readAll 生产表+底稿（分页完整性校验，任一页失败/截短/lastRow漂移→整批 ABORT 退出1）
  │  本地 CAS 预筛（身份/负载/等级/底稿行数）—— 仅作"可提交清单"过滤，不做最终裁定
  ▼
  结构化载荷 rows[] = {row, uuid, keeperRow, level, timeOnly,
                       expectHash, keeperHash, expectBaseHash, batchId}
  ▼
ts_post.py 运输层（默认冻结，TS_WRITE_FREEZE=1；GAS 302→GET 取回响应体）
  ▼
GAS doPost → tsSoftDelGuarded(e)         ← 服务端动作（A1d）
  │  acquireLock()
  │  for each row:
  │    readProdRow(row)        重读实时值
  │    UUID_DRIFT 校验（身份）
  │    ALREADY_SOFTDEL 幂等跳过（诚实返回 ok:false）
  │    KEEPER 存在且未软标
  │    TARGET_DRIFT / KEEPER_DRIFT：实时 _sdNormHash(2..13列) 与请求三级 hash 比对
  │    PAYLOAD_DIFF：target 与 keeper 14 列负载逐列相同（timeOnly 仅豁免列0）
  │    PERIOD_LOCKED：业务日期在锁定期默认拒（除非独立 clearance）
  │    A 级：readMasterByUuid(uuid) 恰 1 行且 BASE_DRIFT 比对；B 级：底稿 0 行
  │    writeProdO(row,'TRUE') 且 writeProdO 后回读确认 ==TRUE 才记 wrote
  │  releaseLock()
  │  诚实 journal：逐行 {row,ok,wrote,reason}；任一失败 → 批次 ok=false（不暗示原子回滚）
  ▼
执行器每批后独立 rereadO（只读通道）确认 O==TRUE（不信任返回声明）
```

**关键改动**：客户端不再裸发 `[row,15,TRUE]`；改为把"身份 + 负载 + keeper + 底稿映射 + 三级 hash"作为契约一起发往服务端，由服务端在锁内闭环校验后写并回读。CAS 的"比较"动作本身发生在服务端、发生在锁内、发生在重读实时值之后——这正是 Tom 点 1 要求闭合的位置。

## 2. 契约（tsSoftDelGuarded 的失败封闭语义）

| 维度 | 规则 |
|---|---|
| 失败封闭（fail-closed） | `dry` 默认 `true`（不写）；`sheet` 锁定 `PL_DB_SHEET`，拒绝调用方覆盖 |
| 结构化校验 | 拒绝 `row==keeperRow` / 重复目标 / 越界 / `level∉{A,B}` / 未知字段（白名单外一律拒） |
| 三级 hash | `targetHash`/`keeperHash` 取规范化的 2..13 列内容指纹（djb2）；A 级额外 `expectBaseHash` |
| UUID 身份 | 实时 `I 列` 必须 `==` 请求 `uuid`，否则 `UUID_DRIFT` |
| 幂等 | 已软标行返回 `ALREADY_SOFTDEL`（诚实 `ok:false`，不虚构 `ok:true`） |
| 负载一致 | `TARGET_DRIFT`/`KEEPER_DRIFT`：实时 hash 须匹配；`PAYLOAD_DIFF`：14 列逐列相同（timeOnly 仅豁免列 0） |
| 期锁 | 业务日期 `<` 锁定期起点 → `PERIOD_LOCKED`（默认拒；独立 `clearance` 才放行，默认不放开门禁） |
| 等级裁定 | A 级：底稿恰 1 行且 `BASE_DRIFT` 比对；B 级：底稿 0 行（`BASE_HAS_MATCH` 拒） |
| 防降级 | 来自 `safe` 清单 → 预期 A（底稿 bc==1），来自 `notInBase` → 预期 B（bc==0）；bc 偏离即拒，不悄悄降级 |
| 写确认 | `writeProdO` 后回读 `O` 列 `==TRUE` 才记 `wrote`（否则 `WRITE_NOT_CONFIRMED`） |
| 诚实上报 | 逐行结果；任一失败 → 批次 `ok=false`（不暗示已完成全批） |

**规范化一致性**：Node 核心 `ts_softdel_core.js` 与 GAS `tsSoftDelGuarded` 共用同一套 `_sdNorm`/`_sdNormHash`（数值 `String(Number(x))` 消除 `"8.0"`/`8` 差异；hash 取 2..13 列、排除日期列 0/1）。GAS 端 `tsSoftDelGuarded`（RemoteActions 全量文件第 1214 行起）与 Node 核心语义逐条对齐，标记齐全：`TARGET_DRIFT/KEEPER_DRIFT/BASE_DRIFT/PERIOD_LOCKED/ALREADY_SOFTDEL/PAYLOAD_DIFF/UUID_DRIFT/WRITE_NOT_CONFIRMED`。

## 3. 完整性（回应 Tom 点 2/3/4）

- **分页完整性（点 4）**：`readAll` 逐页记录请求/实际范围与行数；任一页**读取失败（0 行）**或**截短（不足期望且未到末行）**→ `ok=false`；末页允许 < 期望但须抵达 `lastRow`；`lastRow` 漂移由二次探测判定。任一 `ok=false` → 执行器 **ABORT 且退出 1**，绝不把"空/缺页"误当"底稿 0 行 = B 级"放行。
- **响应严格解析（点 2）**：每批响应须为对象、`batchId` 匹配、逐行**一一对应**（缺行/多行/额外行即拒）、`ok=false` 即拒。杜绝"返回声称成功就当成功"。
- **独立后验（点 3）**：仅当服务端确实写了（`dry!==true`）才用**只读通道** `rereadO` 独立回读这些行 `O==TRUE`，不信任返回声明；不符即中止。
- **防降级（点 4）**：见 §2 防降级行。来源清单决定预期等级，bc 偏离直接拒，不会把 A 级当 B 级悄悄放行。
- **响应丢失（点 2/3）**：响应非 JSON / 非对象 / `batchId` 不符 / 行不一一对应 → `FAIL`、登记不明、**不盲重试**；提供 `--status` 只读回读确认已写（避免重复写）。

> 说明：此前邮件称"每批回读"但实际未见独立后验——现已落实为**每批后独立 `rereadO`**，faithful harness 场景 B 显式断言"apply 后该行 O=TRUE（独立回读确认）"。
