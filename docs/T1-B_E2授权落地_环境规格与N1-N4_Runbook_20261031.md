## 3 执行者为什么可以不依赖外部人员

Tom 要的独立性实质是"过程不可篡改、无人既当运动员又当裁判"。本稿用三条机制等价承载：

1. **不可篡改**：证据报告带**时间戳 + HMAC-SHA256 哈希签名**，Rita 无法在实验后修改结果（改则哈希失配）。
2. **可复现**：采集脚本与实验代码**全文公开于审计仓**，Tom 可独立重跑比对 → 等价于第三方复核。
3. **裁判仍在外部**：最终核对方是 Tom（独立于 Rita 团队），"运动员/裁判分离"成立。

> 诚实界定：此路径**不等于第三方自然人核验**，也不据此声称"生产已安全"。它是 Rita 单人负责现实下、可推进且不降低证据强度的等价替代。

## 5 N1–N4 Runbook（含 Tom 第12轮新增负例）

> 全部在 §2 隔离环境下实跑，禁止触碰生产。**每一步中断后重启**均须重进入路径验证（Tom 第12轮："每步中断重启"）。

### N1 · 跨进程真实互斥（两独立项目 + 同资源）
- **做法**：writer A / writer B（两个独立 GAS 项目）并发请求同一 `ssId` 的守卫写。
- **判据**：同一时刻仅一方获锁；另一方收到 `CENTRAL_LOCK_BUSY` 或排队后执行，**无交错、无双写、无 fence 回退**。
- **负例**：模拟锁不可用/持有超时 → 必须失败登记，**不得降级为 OWN 直写**。

### N2 · 崩溃恢复端到端 + 状态机仅恢复目标行（**对应 v12 重构**）
- **做法**：构造 CRASH_PENDING 行（本次 token 授权涵盖的目标行集合 `targetRows`），再模拟三处崩溃：
  1. 落处置后、翻转前崩（stage=DISPOSED）→ 重试应**只翻目标行**（`toFlip`），`stage→FLIPPED`；
  2. 翻转后、刷缓存前崩（stage=FLIPPED）→ 重试应刷缓存并 `stage→CACHED`；
  3. 完成后再重试（stage=CACHED）→ **只回读可信记录**（`idempotent:true`），不重写审计、不重复翻转。
- **判据**：`flippedTargets == authorizedTargets`（本次授权目标全恢复）；`newPendingOutsideScope` 如实计数；**完全结束后账本无 CRASH_PENDING 残留**。

### N3 · 释放失败不丢锁
- **做法**：使锁释放路径抛错。
- **判据**：日志记录 `RELEASE_FAIL`（**不得伪报 `RELEASED`**）；失败可见、可追溯。

### N4 · 令牌与账本 fail-closed（**Tom 第12轮要求的负例全量覆盖**）
每个用例均须被**拒绝**（fail-closed），并给出确切 reason：

| 负例 | 期望拒绝码 |
|---|---|
| 伪造签名（sig 不匹配） | `RESOLVE_TOKEN_INVALID` |
| **借用旧 nonce**（nonce 存在但不属该 maxf 范围） | `RESOLVE_NONCE_SCOPE_MISMATCH`（v12 新增，修复 Tom"只查 nonce"） |
| 与原请求摘要不符（篡改 digest） | `RECOVER_DIGEST_MISMATCH` |
| **持久记录摘要【缺失】**（清空 digestAtRequest） | `RECOVER_RECORD_DIGEST_MISSING`（v13 新增：不再允许“缺失即跳过比对”） |
| **新增 pending**（令牌未涵盖的新行） | `outOfScopeCount>0` → **不刷 B1、不推进 stage 到 CACHED**，返回 `complete:false / partial:true`，须另领新令牌覆盖后重跑 |
| **目标行 JSON 损坏**（改成非法串） | `RECOVER_TARGETS_MALFORMED`（v13 新增：不再 catch→空数组） |
| **目标行集合被事后增减**（篡改 targetRows） | `RECOVER_TARGET_DIGEST_MISMATCH`（v13 新增：第 11 列 targetDigest 密钥绑定） |
| **目标行【为空】**（抹掉 targetRows） | `RECOVER_TARGETS_MISSING`（v13 新增） |
| **未知 / 空 stage**（手动写入 stage=`X` 或留空） | `RESOLVE_STAGE_UNKNOWN`（v13 新增：stage 白名单 DISPOSED/FLIPPED/CACHED） |
| **stage=CACHED 但范围内仍有 pending**（记录与状态不一致） | `RECOVER_STATE_INCONSISTENT`（v13 新增） |
| **持他人 nonce 命中记录后回显他人身份** | `RECOVER_IDENTITY_MISMATCH`（v13 新增：rec.approver/verifier 必须 == 当前令牌身份） |
| 跨资源（resourceId ≠授权表） | `RESOLVE_RESOURCE_MISMATCH` |
| 职责不分（approver == verifier） | `RESOLVE_SEPARATION_DUTY_VIOLATED` |
| 未来时间 / 过期 | `RESOLVE_TOKEN_FUTURE` / `RESOLVE_TOKEN_EXPIRED` |
| 每步中断重启 | 由 §N2 stage 机保证幂等推进，不丢审计、不重复写 |
| 重复/零值/非法状态 fence | `LEDGER_DUP` / `LEDGER_ZERO` / `LEDGER_BADSTATUS`（fail-closed，不自动升级 PASS） |

## 6.5 证据可复核性三件套（回应 Tom 16:21Z 第13轮技术条款）

Tom 第13轮指出：“由同一提交方控制的采集器与密钥不能单独证明隔离、权限和独立性；请保留原始证据、采集器固定版本与验证方法”。
其中**可由我方纯技术落地**的三条，本稿一并固化（不涉人事安排，不需 Tom 承担 action）：

| # | 条款 | 我方技术落地 | 可核验证据 |
|---|---|---|---|
| E-1 | **保留原始证据** | 采集器把每次 API 调用的**原始响应体**（Drive `files.get` / Sheets metadata / GAS `projects.getContent` / 部署列表）原样落盘为 `raw_<api>_<ts>.json`，**不做任何字段筛选或改写** | 原始 JSON + 逐文件 SHA-256；任何第三方可用原始数据重算，与摘要报告逐字节对照 |
| E-2 | **采集器固定版本** | 采集器以 `commit hash + semver tag` 固化并自校验：运行时打印自身 sha256 与 git HEAD；报告内嵌 `collector_version` / `collector_sha256` / 运行命令 | 任何人 clone 同 commit 复跑，应得到**同一份处理逻辑**；版本漂移即视为证据失效 |
| E-3 | **验证方法公开** | 随报告附独立 `verify_evidence.py`（只读、不依赖我方密钥），输入原始 JSON 即可独立重算哈希与一致性结论 | 重算结果与报告哈希比对；不一致即报告作废 |

**诚实边界（不弱化）**：三件套**提高可追溯性与可复现性**，但**不能替代**独立核验者的隔离/权限核证；
它们使“任何有权限的第三方可以事后复核”，**不使**本报告变为有效生产证明或独立第三方证明。核验者安排属 Rita 侧自决事项，不计 Tom 待办。
