## 六点 → 修复落点

### Pt1 · 加载失败测试未走真实路径
- **问题属实**：旧 `__test_setCore(null)` 后 `_CORE===null !== undefined` 使 `loadCore` 首句直接 return，`__test_forceLoadThrow` 强制分支根本没到；且该分支不在 `require` 的 try/catch 内——所谓"真实加载失败"测的是假路径。
- **修复**：`loadCore` 改为调用**可注入 loader** `_REQUIRE_CORE`（默认 `require('../ts_leave_tip_core.js')`）；真实 `require` 失败由 `try/catch` 真正捕获，`_CORE` 置 `null` 且发 `ERR_LOAD` 固定码（不含原始 message）。新增接缝 `__test_setLoader()` / `__test_resetCache()` / `__test_coreState()`。
- **测试（新增/改）**：清空缓存 + 注入确实 `throw` 的 loader → 断言 `FETCH_FAILED` + `loadCalls>=1`（require 分支真被调用）+ `_CORE===null`（catch 生效）；OFF 下两入口断言 `loader` 零调用 + 缓存未触达。

### Pt2 · employeeId 仅 truthy 检查；frozenResolver 非不可变快照
- **问题属实**：`if (!pr.employeeId)` 对空白串 `" "`、数组 `[]`、对象 `{}` 均放行；`frozenResolver` 返回的是可变 `principal` 引用而非最小快照。
- **修复**：`resolvePrincipal` 收紧为 `typeof pr.employeeId === 'string' && pr.employeeId.trim()`；主体解析一次后固化为 `Object.freeze({ employeeId })` 最小快照经 `frozenResolver` 返回核心（杜绝双解析 + 可变引用）。
- **测试（新增）**：解析器返回空白串 / 数组 / 对象 / 数字 → 全部 `PRIVACY_BLOCKED`；解析器 `throw` → `PRIVACY_BLOCKED`（不外逃）；`handleRequestSafe` 同样严格（双入口一致）。

### Pt3 · 日志仍打原始 message；wrapResponse 转发非白名单 status
