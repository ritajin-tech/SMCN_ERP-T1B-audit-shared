## §5 哈希核对精度勘误（请在逐件比对前先读）

> 这是本轮实测发现、会直接影响你方核验结论的**口径问题**，不是结论修订。

- **现象**：`git ls-tree -r --name-only <commit>` 在默认 `core.quotePath=true` 下，把中文路径做八进制转义并加双引号。此时 `grep -c '^docs/'` 只数到纯 ASCII 路径，计数会**少算 115 件**。
- **实测**（同一提交 `381aab3`）：

| 命令 | docs+evidence 计数 |
|---|---|
| `git ls-tree -r --name-only 381aab3 \| grep -cE '^(docs\|evidence)/'`（默认转义） | **222（错误）** |
| `git -c core.quotePath=false ls-tree -r --name-only 381aab3 \| grep -cE '^(docs\|evidence)/'` | **337（正确）**：docs 124 / evidence 213 |
| `git -c core.quotePath=false ls-tree -r --name-only 9363638 \| grep -cE '^(docs\|evidence)/'` | **332（正确）** = v77 基准清单件数 |

- **结论**：`evidence/v77_hash_inventory_20261107.json` 的 **332 件没有错**。以 `9363638` 的 tree 复算，路径集合双向差集 **0**，逐件字节数与 SHA-256 差异 **0**。若你方按默认 `git ls-tree` 看到 222 件，是路径转义造成的计数差，不是缺件。
- **正确复核命令（系统自带 git，不运行我方脚本）**：

