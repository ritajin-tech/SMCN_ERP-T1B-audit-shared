### #2 锁句柄不得调用方自造（服务端受信锁适配器签发）

| 项 | 内容 |
|---|---|
| 文件:行 | `tools/ts_clearance.js:109–171`（`_lockError` / `makeHeldLock`）、新增 `tools/ts_lock_adapter.js:48–77` |
| 问题 | `held/id/released` 是调用方可任意构造的普通对象，`lockId` 还是可选 ⇒ 任何人拼 `{id,held:true}` 都能声称持锁；无法证明与期锁同域、更无法证明跨进程串行 |
| 改法 | ① `ctx.lockId` **由可选改必填**且与 `lock.id` 严格相等；② `lock.id` 必须非空字符串；③ 句柄须携带服务端 attestation `{alg:'HMAC-SHA256', dom, sig:HMAC(secret, id|dom)}`，验签不过 → `LOCK_ATTEST_MISSING/LOCK_ATTEST_BAD`；④ 声明域 `ctx.lockDomain` 与 `attest.dom` 不一致 → `LOCK_DOMAIN_MISMATCH`；⑤ **刻意不设 env 逃生口**（此处一旦可放行，缺陷整体回归）；⑥ 新增 `ts_lock_adapter.js`：把“取锁→立即签发签名句柄→释放时撤销 attest”封装成唯一入口（secret 须来自服务端配置，缺则从不被静默造锁） |
| 验收 | 未签名句柄 `LOCK_ATTEST_MISSING`、他人密钥签发 `LOCK_ATTEST_BAD`、域不符 `LOCK_DOMAIN_MISMATCH`、缺 lockId `LOCK_ID_MISSING`、受信适配器句柄可消费；集成 9b（core 自造未签名句柄 → 零写） |

| 项 | 内容 |
|---|---|
| 文件:行 | `tools/ts_clearance.js:27–33`（`MAX_TTL_MINUTES=15`，**硬上限无 env 逃生口**）、`:62–90`（按 signer 索引密钥的 `_signerRegistry` + `trustSigner`）、`:218–280`（CAS 消费）、`:308–346`（`reconcileUnknown`）、新增 `tools/ts_clearance_filestore.js:85–110`（跨进程文件账本 CAS） |

## 6. 我方仍未闭合清单（诚实披露）

1. **服务端持久账本**：GAS 侧 PropertiesService 绑定未实现，文件账本仅跨进程参考。
2. **恢复状态机**：仅到“禁止盲重试 + 结构化对账登记”，非完整状态机。
3. **independent issuer / verifier**：signer 登记仍是**内存表**；生产须换成服务端受信配置或独立签发服务。
