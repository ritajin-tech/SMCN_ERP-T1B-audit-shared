## 一、五项阻塞 → 修复对照

### Block1：handleRequestSafe 无 try/catch；getLeaveTipSafe 的 catch 不能捕获异步 reject
**修复**：两入口均加 try/catch；新增 `settle()` 统一兜底——若核心返回 Promise（当前核心为同步，但契约不假设），对其 `.catch` 也返回可用性回退；不再声称"四路径全部不阻塞"未证。
```js
function settle(res){ if(res&&typeof res.then==='function'){ return res.then(r=>r).catch(e=>availabilityFallback((e&&e.message)||e)); } return res; }
function handleRequestSafe(req){ if(!FEATURE_ENABLED) return DISABLED; const core=loadCore(); if(!core) return availabilityFallback(...);
  try{ const out=settle(core.handleRequest(req)); if(out&&typeof out.then==='function') return out.then(r=>wrapResponse(r,null)).catch(e=>availabilityFallback(...)); return wrapResponse(out,null); }
  catch(e){ return availabilityFallback((e&&e.message)||e); } }
```
**负例验证**：同步抛错→FETCH_FAILED；异步 reject→FETCH_FAILED（均不崩、submitAllowed:true）。

### Block2：require 与 API 选择在模块初始化、开关判断之前；依赖缺失时"默认关"不能兜底
**修复**：依赖改为**开关判断之后惰性加载**（`loadCore()`），包在 try/catch；加载失败 `_CORE=null`，入口返回可用性回退，默认关仍能兜底，不会因 require 抛错致模块整体加载失败。
```js
let _CORE=undefined; function loadCore(){ if(_CORE!==undefined) return _CORE; try{ const CORE=require('../ts_leave_tip_core.js'); _CORE=(CORE&&CORE.getLeaveTip)?CORE:(CORE&&CORE.API?CORE.API:CORE);}catch(e){_CORE_ERR=String((e&&e.message)||e);_CORE=null;} return _CORE; }
```
**负例验证**：注入"依赖缺失"→FETCH_FAILED 不崩。

### Block3：无本人身份绑定/服务端解析/镜像行级授权/响应最小化的实现证据；隐私封闭失败与填报可用性未分离；opts.now 把合法 0 当未提供

- 镜像行级授权（纵深防御）：调用核心**前**即在包装层把镜像行过滤到仅本人（`filteredMirror`），核心再过滤一次。

- `opts.now` 修正：`opts.now !== undefined` 判断（0 为合法受控时钟值，不再被 `!!now` 丢弃）。
```js
const now = (opts && opts.now !== undefined) ? opts.now : undefined;
if(res.status==='AUTH_REQUIRED'||res.status==='UNAUTHORIZED') return Object.assign({},privacyBlocked(res.status),{rawStatus:res.status});
```
**负例验证**：无主体→PRIVACY_BLOCKED；非唯一→PRIVACY_BLOCKED；镜像含他人行→包装层滤除仅留本人；opts.now=0 透传非 undefined；核心身份状态→PRIVACY_BLOCKED 分离。
